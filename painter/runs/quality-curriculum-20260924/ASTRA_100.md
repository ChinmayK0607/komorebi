# Astra-high teacher campaign: 100 reference photos

**Question.** Can high-reasoning visual code teachers supply enough *distinct*, aesthetically acceptable reference-to-painting trajectories to improve the student, when the prior 38-row, 16-scene multi-turn SFT regressed? The matched student baseline remains the public photo-SFT step-512 adapter (weight SHA-256 `bea72b066986faa1b92b9dc539c710093181ee916b99323e2b2498f318ac1740`) on the fixed 28-photo development manifest (SHA-256 `9943878cc43d48f1cf9ff60e5af633089bf2bd8d45141216531363cad8f1c878`). The development set is never a teacher target.

The [100-reference manifest](reference-manifest-astra-100.json) is the exact complement of those 28 photos in the official 128-image COCO128 archive (SHA-256 `61e5e3028863d8ffc3b81d6a514603954889f0edd5e4b44c4ce60b2da99aeb8e`). All 100 image hashes are distinct; 48 already have MiMo wave-5 candidate histories. Manifest SHA-256: `206f9ff075b401bde13ad90e284ff00370c4a927e35497ee24ccacf07fa8ce6d`. The remaining 52 are newly staged training references. These are *targets for data generation*, not 100 completed or approved teacher examples. COCO object-count buckets are rough difficulty proxies; actual visual structure and beauty decide admission.

Three concurrent `gpt-6-astra` agents at high reasoning effort author four programs each in the first pass, with separate easy-a, hard-a and hard-b scenes. They inspect each photo and actual MiMo canvas when available. Every authored program is untrusted until the pinned Linux renderer produces a valid canvas and a human/parent review finds it sufficiently attractive and closer to the reference. Accepted correction examples will include the exact prior canvas, prior program where it fits the model processor budget, renderer feedback, and the improved complete program; failed renderings remain evidence, never supervised targets. Earlier approved MiMo turns may also supply trajectory examples, but raw later turns do not become targets merely by being later.

Source candidates and rendered evidence are stored outside Git. The [packager](package_astra_wave.py) binds programs to reference hashes and the actual MiMo prior-canvas hashes. [Publisher](publish_astra_source.py) uploads each small source bundle to the public HF dataset and anonymously verifies its SHA-256. [Cloud renderer](render_astra_cloud.py) and [finite launcher](run_astra_render_cloud.sh) replay candidates on Codex Cloud Linux with a renderer smoke check and publish hash-verified result archives. No Lium GPU is used for data generation or rendering. GPU training follows only after visual admission, Qwen processor-length audit and a reviewed first-/revision-turn mix.

**Initial state, 26 September 2026.** The three repaired MiMo n12 shards (easy-a, hard-a, hard-b) are publicly hash-verified and locally collected. They contain 36 scenes and 84 renderer-valid turns, but 22 episodes ended in renderer errors. These counts describe validity, not aesthetic quality or SFT yield. Provider costs are unavailable because the Gateway omitted cost fields; the reported zero-dollar sum must not be interpreted as free. Astra agent usage is likewise not yet instrumented as monetary cost. Parent visual review and Astra Linux renders are pending.
