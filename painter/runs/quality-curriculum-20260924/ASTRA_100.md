# Astra-high teacher campaign: 100 reference photos

**Question.** Can high-reasoning visual code teachers supply enough *distinct*, aesthetically acceptable reference-to-painting trajectories to improve the student, when the prior 38-row, 16-scene multi-turn SFT regressed? The matched student baseline remains the public photo-SFT step-512 adapter (weight SHA-256 `bea72b066986faa1b92b9dc539c710093181ee916b99323e2b2498f318ac1740`) on the fixed 28-photo development manifest (SHA-256 `9943878cc43d48f1cf9ff60e5af633089bf2bd8d45141216531363cad8f1c878`). The development set is never a teacher target.

The [100-reference manifest](reference-manifest-astra-100.json) is the exact complement of those 28 photos in the official 128-image COCO128 archive (SHA-256 `61e5e3028863d8ffc3b81d6a514603954889f0edd5e4b44c4ce60b2da99aeb8e`). All 100 image hashes are distinct; 48 already have MiMo wave-5 candidate histories. Manifest SHA-256: `206f9ff075b401bde13ad90e284ff00370c4a927e35497ee24ccacf07fa8ce6d`. The remaining 52 are newly staged training references. These are *targets for data generation*, not 100 completed or approved teacher examples. COCO object-count buckets are rough difficulty proxies; actual visual structure and beauty decide admission.

The [coverage assignment](astra-100-assignments.json) partitions all 100 IDs exactly once: three four-scene correction groups from wave 5, six four-scene first-paint groups, then eight eight-scene groups mixing the remaining 36 wave-5 and 28 newly staged photos. It is a generation plan, not an admission count; group status must be read from hash-verified source/render receipts. Wave 3 is a separate second-pass correction on already assigned scenes, so it adds trajectories but not distinct reference coverage.

Three concurrent `gpt-6-astra` agents at high reasoning effort author four programs each in the first pass, with separate easy-a, hard-a and hard-b scenes. They inspect each photo and actual MiMo canvas when available. Every authored program is untrusted until the pinned Linux renderer produces a valid canvas and a human/parent review finds it sufficiently attractive and closer to the reference. Accepted correction examples will include the exact prior canvas, prior program where it fits the model processor budget, renderer feedback, and the improved complete program; failed renderings remain evidence, never supervised targets. Earlier approved MiMo turns may also supply trajectory examples, but raw later turns do not become targets merely by being later.

Source candidates and rendered evidence are stored outside Git. The [packager](package_astra_wave.py) binds programs to reference hashes and the actual MiMo prior-canvas hashes. [Publisher](publish_astra_source.py) uploads each small source bundle to the public HF dataset and anonymously verifies its SHA-256. [Cloud renderer](render_astra_cloud.py) and [finite launcher](run_astra_render_cloud.sh) replay candidates on Codex Cloud Linux with a renderer smoke check and publish hash-verified result archives. No Lium GPU is used for data generation or rendering. GPU training follows only after visual admission, Qwen processor-length audit and a reviewed first-/revision-turn mix.

**Initial state, 26 September 2026.** The three repaired MiMo n12 shards (easy-a, hard-a, hard-b) are publicly hash-verified and locally collected. They contain 36 scenes and 84 renderer-valid turns, but 22 episodes ended in renderer errors. These counts describe validity, not aesthetic quality or SFT yield. Provider costs are unavailable because the Gateway omitted cost fields; the reported zero-dollar sum must not be interpreted as free. Astra agent usage is likewise not yet instrumented as monetary cost. Parent visual review and Astra Linux renders are pending.

**100-scene coverage and provisional selection — 26 September 2026.** Eight additional eight-scene Astra-high shards (`coverage-g` through `coverage-n`) produced 64/64 renderer-valid canvases on finite Codex Cloud Linux CPU jobs. Together with the repaired first 36, the [candidate index](astra-candidate-index-100.json) now covers exactly **100 distinct valid train references**, with per-image reference/program/canvas hashes, public bundle receipts, source commits and parent review labels. Its SHA-256 is `029d3c67120281aff27fe6246215c105b25ea2367d3eb5e129ca0cc4f2ba7438`; the [public HF copy](https://huggingface.co/datasets/CK0607/komorebi-painter-teachers/blob/main/curricula/astra-high-100/candidate-index-100.json) was anonymously fetched and hash-verified. The [first-36 review](astra-visual-review-first36.json) and [next-64 review](astra-visual-review-coverage64.json) record concrete weaknesses for every image. The nonblind parent screen marks 70 promising and 30 needing revision, but these are *data triage labels*, not pairwise wins or student outcomes. Human anatomy, faces, fur and painterly texture remain recurring failures; the valid examples often look like flat illustrations. The [filtered local gallery](../../collected/quality-curriculum-20260924/astra-high-100/progress.html) shows reference, available prior canvas, rendered Astra image, weakness and provisional label.

The [pilot admission record](astra-sft-admissions-pilot54.json) selects 54 diverse, visually stronger first-paint targets from those 100: 39 reference-only inputs and 15 inputs with an earlier actual canvas and feedback. Every target is a complete program bound to its hash-verified Linux render. The exported 21,711,889-byte JSONL has SHA-256 `8213dbddc24177ff6ae2e03dd3eb9f398c169aca8ab73949fa14728ae328cb6c` and is [public on HF](https://huggingface.co/datasets/CK0607/komorebi-painter-teachers/blob/main/curricula/astra-high-100/sft-pilot54.jsonl); the audit and admissions files are public alongside it and all three were anonymously hash-verified after upload. **This is a provisional SFT pilot pool, not proof that training on it helps.** The previous matched 38-row/16-scene multi-turn SFT regressed, so no GPU run should start from these rows before the exact Qwen processor-length audit and a matched initializer comparison are specified. The remaining 46 first-paint examples are retained as candidate states for future pairwise RL or revision, never silently used as positive targets. Astra authoring monetary cost was not exposed by the agent session; Codex Cloud CPU job cost and utilization were not instrumented, and there was no GPU rental or paid teacher API call in this campaign. The next decision is whether a small, matched SFT pilot can improve the held-out 28-photo visual result without flattening style, then whether visually verified revisions can form a separate multi-turn mix.

**Subsequent student test, 26 September 2026.** The [first-paint SFT pilot](ASTRA_FIRSTPAINT_RESULT.md) trained the 39 reference-only examples from this pool with 41 distinct procedural-retention examples for 20 updates, initializing the public photo-SFT step-512 adapter. The exact processor audit and public checkpoint upload passed, but the frozen 28-photo matched comparison regressed: 19/28 baseline versus 14/28 trained first-turn valid canvases, and 19/28 versus 15/28 final valid canvases. Parent visual inspection also favors the initializer overall. This subset is therefore not an endorsed SFT recipe; do not read the earlier provisional admission language as a successful training result. The 21 revision rows were not trained in this pilot because their omitted prior-program state differed from the live prompt.
