# Reviewed-turn SFT wave 4: matched result

The 40-update multi-turn SFT pilot is **not promoted**. It initialized exactly from the public photo-SFT step-512 adapter and trained successfully, but the frozen 28-photo, two-turn evaluation favors that initializer. The public step-24 and step-40 adapters remain available as research artifacts, not recommended painter checkpoints. [Inspect all reference, first-paint and revision canvases](../../collected/quality-curriculum-20260924/multiturn-sft-wave4/review/index.html).

All three policies used the same frozen reference manifest (SHA-256 `9943878cc43d48f1cf9ff60e5af633089bf2bd8d45141216531363cad8f1c878`), seed, scaffold, renderer, token limit and two-turn cap. Each policy saw its *own* prior canvas on turn two; this measures end-to-end painting, not fixed-draft correction. The counts above are renderer validity, not aesthetic scores. Renderer service failures affected three baseline, one midpoint and two step-40 episodes; they remain visible in the traces and are not silently counted as model program errors. Mechanical final validity includes a saved valid first canvas when the second action fails.

Visual inspection of the 28 side-by-side final canvases also favors the baseline overall. For example, its table/cup scene `000000000127`, kitchen `000000000089`, cat `000000000599`, and food `000000000584` retain more recognizable structure than the step-40 result; several step-40 cases have no canvas. The step-40 airplane `000000000081` and toilet `000000000636` are useful counterexamples with visible structure, so this is a mixed regression rather than uniform failure. This is a parent inspection, not a blinded pairwise win-rate. The larger source images and individual first/revision paintings are linked in the gallery.

The training input was only 38 approved targets over 16 scenes, repeated to 120 reviewed exposures and mixed with 40 procedural exposures. It supervised each approved teacher turn as a separate example using the reference, prior canvas and feedback, with the next *complete* program as the assistant target. It did **not** train a contiguous 4–6-turn assistant history. The full prior program was removed from revision rows after the exact 16k processor audit found a 17,803-token row. At evaluation, the model can see the prior program in conversation, so the revision training and live prompts are not identical. First-paint validity fell more sharply than final validity, which points to distribution/retention failure beyond just the repair prompt. The step-40 model rescued five invalid first attempts, but it also repeated the identical invalid reply seven times; case `000000000419` repeated an unsupported `Brush` constructor after the renderer reported `Brush is not defined`. Other repeated failures include invented `p5.brush` constructors, unsupported brush names and JavaScript syntax errors. The training targets passed a narrow teacher contract check, but that alone did not prevent student API hallucinations.

The corrected finite campaign completed training and all evaluations with exit code zero. The first launch attempt had two pre-update setup faults; no optimizer update occurred in it. The final public adapter is [step 40](https://huggingface.co/CK0607/qwen3.8-27b-brush-painting/tree/e80af8c90f9dfa2d7a22696dbaf9aaed3d30c8ae/multiturn-sft-20260925-v1/step_40), weight SHA-256 `b026b2d4d9ca4d77ffdc8db856d7c72f385af44ca3aa8273ff7fc31fec4443e3`. The full 485-member evidence archive is [public on Hugging Face](https://huggingface.co/datasets/CK0607/komorebi-painter-evaluations/tree/afaa1219e5172c86e4805753927095c56b062cdc/multiturn-sft-20260925-v1), SHA-256 `d4c9e76788600095f3dc2d1b139ecf568c5f2a04ac16a491868fb396fd6bcc6e`, anonymously downloaded and hash-verified. The local archive has the same hash. The Lium node is released; the final listed spend before deletion was about **$4.17** at $2.38/hour. During the 14:46:32–15:07:58 UTC training window, 129 ten-second samples per GPU showed mean utilization 73.3% for GPU 0 (trainer) and 93.8% for GPU 1 (parallel baseline evaluator); this bounded window does not describe full-rental utilization.

**Next decision:** Keep step 512 as the comparison checkpoint. Before another GPU run, generate a much larger, distinct-scene curriculum, with easy shapes/objects, compositions, and real photos; retain visually reviewed first paints, valid revisions, and explicit invalid-program repair transitions. Use MiMo Flash where it can pass a render and visual review, Pro for hard cases. Avoid three repeats of a 16-scene set as the main signal. Match SFT prompt state to the live evaluator, particularly whether the previous program is present, and check first-turn contract validity on a cheap inference sample before long training. Keep a disjoint photo holdout and evaluate both first-turn and revision quality. This is a proposal, not evidence that the next training run will work.
