# Distinct-scene teacher wave 5

**Hypothesis.** The preceding multi-turn SFT regressed partly because only 38 approved turns from 16 scenes were repeated three times. Expand *distinct* reference coverage before another training run, and retain actual first-paint and revision canvases for visual admission. The matched student baseline remains the public photo-SFT step-512 adapter (weight SHA-256 `bea72b066986faa1b92b9dc539c710093181ee916b99323e2b2498f318ac1740`) on the fixed 28-photo development manifest (SHA-256 `9943878cc43d48f1cf9ff60e5af633089bf2bd8d45141216531363cad8f1c878`). The wave-4 failure and comparison are in [MULTITURN_RESULT_WAVE4.md](MULTITURN_RESULT_WAVE4.md).

The [source manifest](reference-manifest-wave5.json) selects 48 previously unused COCO128 train photos, disjoint by exact image ID and SHA-256 from the 28 development photos and earlier wave-3 teacher references. It greedily covers different annotated object categories and aspect ratios within two annotation-count buckets: 24 with one to three annotated objects and 24 with four or more. **Annotation count is only a rough clutter proxy, not a guarantee of easy geometry**; the contact sheet in ignored collected data was inspected before generation. The [2.7 MB public source archive](https://huggingface.co/datasets/CK0607/komorebi-painter-teachers/tree/823ff0568e0bd7caf136b94479f4dfccefac11bc/curricula/multiturn-wave5) has SHA-256 `cb388eb0f5552659e837fad3c43cd9f1c26945dba49978421092295373fc733e` and was anonymously downloaded and verified. Manifest SHA-256 is `7f0d5d83361305a2758a12112bf9a037a7c9b88f03eb8a35340d7ec5c6b4975f`.

Four independent, finite Codex Cloud CPU shards each take 12 references. `easy-a` and `easy-b` use MiMo v2.6 Flash for at most four visual turns; `hard-a` and `hard-b` use MiMo v2.6 Pro for at most six. Maximum provider requests are 48, 48, 72 and 72 respectively (240 total); no retries of paid calls, two concurrent provider episodes, one renderer slot per VM, native model output allowance and no token/stroke budget. The teacher sees each actual canvas and renderer feedback before revising. Each shard publishes cumulative 4-, 8- and 12-episode prefixes to public Hugging Face with an anonymous archive hash check. All outputs are **candidates**, including apparently valid renders; visual review must choose good turns and reject regressive, invalid, or off-reference turns before SFT. The source includes no development image. Provider revisions and actual charged cost must be recorded if available; a missing cost field is not zero dollars.

Cloud tasks were dispatched from reviewed source commit `0b5b682` on branch `codex/painter-multiturn-sft`: [easy-a](https://chatgpt.com/codex/tasks/task_e_6ab69f897d2c832b9fc785830684cbaa), [easy-b](https://chatgpt.com/codex/tasks/task_e_6ab69f9eaa80832b99e3e118e4275357), [hard-a](https://chatgpt.com/codex/tasks/task_e_6ab69fa3b7cc832b8fe094103ae0de6c), and [hard-b](https://chatgpt.com/codex/tasks/task_e_6ab69fa98a1c832bae4a0547fb29ab2d). They are finite jobs, not scheduled watchers. Status and admission results are pending.

**Failed first prefix and repair.** All four original n4 prefixes were publicly hash-verified, then all four tasks were cancelled before their n8 prefixes completed. The [easy-b n4 receipt](https://huggingface.co/datasets/CK0607/komorebi-painter-teachers/blob/main/runs/mimo-wave5-easy-b-20260925-n4/receipt.json) verifies archive SHA-256 `2cd20ee8f046c4553fd2c9381244b3d144394bcbf29ae4a5f704ff7076479b79`. Its four first-turn responses totaled 74,518 reported tokens but produced zero canvases: every render failed in approximately 0.08 seconds because the staged config requested 240 seconds while the pinned renderer accepts only 1–180. The same all-`renderer_error` status appears in easy-a and hard-a n4 summaries. This is an infrastructure failure, **not** a judgment of teacher quality. Provider cost fields are missing; the reported $0 sum is not a measured charge. The repaired launcher now runs an actual renderer smoke before any paid call, explicitly passes a 180-second runtime override while retaining the original 240-second request binding for exact response reuse, restores each hash-verified n4 archive, publishes under new `repaired` run IDs, and halts after any prefix consisting entirely of renderer service failures. The original evidence is immutable; repaired runs are separate records. At present no new teacher turns or SFT rows are claimed.

Source and launch files are [prepare_wave5_source.py](prepare_wave5_source.py), [stage_wave5_cloud.py](stage_wave5_cloud.py), and [run_wave5_cloud.sh](run_wave5_cloud.sh). The local source staging and 12-episode dry runs on both model tiers passed with zero paid requests; Linux rendering and Gateway traffic occur in the finite cloud tasks. No Lium GPU or scheduled watcher is involved.

**Training decision after admission.** Do not start another 27B GPU run merely because these 48 candidates finish. Count accepted distinct scenes, renderer-valid turns and real first-to-next visual improvements, then rebuild a non-repeated or lightly repeated SFT mix. Train each accepted turn with its exact reference, prior rendered canvas, failure/visual feedback and a complete next program. The previous wave omitted prior code from SFT but included it in the live evaluator, so prompt-state alignment must be fixed and processor-audited before training. Include explicit invalid-program repair examples rather than relying only on successful teacher revisions. Keep the same matched baseline and inspect first and second turns separately. A new GPU run is justified by reviewed yield, not the number of API responses.

The exporter now has an opt-in `--include-prior-program` mode so the next admitted revision targets can match the live evaluator's `Current program` field. Its default reproduced the released wave-4 reviewed JSONL byte-for-byte (SHA-256 `6de85c426673cae3d81003d84cdf5991d2c7e4288e2fbfc2c4912ccb5e6d0029`). On those 38 rows, 23 have a prior valid program; adding it would push an estimated five rows beyond the old 16k limit, based on Qwen text-token deltas plus the saved exact processor counts. This is a planning estimate, **not** a passed new processor audit. The next data build must either omit those overlong rows, use a verified longer context, or adopt an audited compact representation; it must never silently truncate the supervised target. First-paint rows also need more distinct scenes because their validity fell from 15/28 to 7/28 in wave 4.
