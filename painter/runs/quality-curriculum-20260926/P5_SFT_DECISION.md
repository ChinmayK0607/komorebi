# P5 SFT decision — 2026-09-27

**Decision:** do not train on the 600 raw first-paint programs and do not regenerate all 600 from scratch. Keep native p5 as an allowed painting medium; use opaque native shapes for the major forms and optional p5.brush accents. Repair a diverse slice of the existing pool with actual source/first-paint/render feedback, select better complete programs by visual review, then run a short LoRA canary before expanding further.

The hypothesis for SFT is that diverse, visually selected first paintings and complete render-conditioned revisions improve both structure and aesthetics without sacrificing program validity. The matched initializer is the public photo-SFT step-512 adapter from the previous 28-photo evaluation (17/28 valid final canvases), not the regressed 40-update multi-turn adapter (12/28). Its base is `Qwen/Qwen3.8-27B` revision `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`; adapter revision `adf687e5b321514eda7be6eab050434fdc8e44ff`, weight SHA-256 `bea72b066986faa1b92b9dc539c710093181ee916b99323e2b2498f318ac1740`. A separate frozen holdout must include both text prompts and photographs; training source scenes and source photographs are excluded from it by identity and image hash. A renderer-valid canvas alone is not a beauty label.

Evidence against raw-pool SFT: 595/600 first paintings render, but twelve fixed-seed full-size spot checks were all below the direct high-quality bar. No examples were admitted by the provisional 595-canvas visual triage. Training 38 reviewed turns across sixteen scenes with repetition previously reduced final validity from 17/28 to 12/28 and made first-turn validity worse. Simply making the 600 syntactically valid or translating native p5 calls to brush calls does not guarantee a better source-matched target: in eight direct comparisons the native originals preserved the subject more clearly. The translations can still have independent painterly appeal. `SOL_BRUSH_STYLE_REVIEW.json` records that separate assessment and retains selected conversions as style candidates, without rewriting the original source-fidelity labels.

Evidence for selective repair: in the completed eight-scene teacher wave, all eight selected revisions improve the exact first paint. Five simpler/middle outputs are plausible SFT *candidates* (noodles, metal pot, hedgehog, avocados, carved duck); three remain relative-only due to missing source structure or an inconsistent brief. The selected valid programs all use native p5 geometry with brush calls, matching the intended opaque-form-first medium. The eight-scene review and exact hashes are in `REPAIR_WAVE_8_REVIEW.json`. Eight scenes are too narrow to infer the yield of the whole pool.

The next source set is the hash-pinned 100-scene `REPAIR_HUNDRED_PLAN.json`: 50 text, 50 photo, 15 native-only programs, diverse source batches and categories, ten finite CPU shards. Its public archive is an input bundle, not a set of SFT targets. For each completed scene, preserve every full teacher turn, actual rendered canvas, errors and token counts. Review the best valid canvas against the true source and first paint. Admit a turn as positive SFT only when it is a substantial visual improvement with a coherent subject and no important source mismatch; otherwise retain it as a relative preference or correction state. Preserve the entire prior program in revision inputs, or omit it in both training and live inference: the previous run's mismatch between those states is a confounder. Include text/photo and easy/hard balance; do not multiply a handful of scenes until they dominate the gradient.

Retain all fifteen and preserve the two dimensions: prioritize source-faithful rows for paired SFT, and consider the others for style/preference use. A focused brush-feel refinement slice should add painterly marks without losing the now-appealing structure; a blanket renderer translation is not justified by this feedback. After a shard publishes, `collect_repair_hundred.py --shard flash-00` (or another submitted shard) anonymously downloads its split public result, checks archive and source/program/canvas hashes, and builds a source/first-paint/all-valid-turn review page. A source-matched gallery is required before admitting any new SFT row. Multiple already-published shards can be combined by repeating `--shard`.

**LoRA canary after reviewed data exists:** train a short continuation from the exact step-512 adapter, with the same prompt state as the intended inference harness and a small established contract/retention mix. Keep p5 and p5.brush both legal; never require translucent brush fills for primary objects. Compare initializer and canary at the same token/turn budgets on frozen text and photo holdouts, reporting first-turn validity, final validity, blinded pairwise visual preference, unchanged/repeated actions, token use, and explicit censored render failures. Continue only if the paintings visibly improve without a severe validity collapse. This is a learning decision tied to observations rather than an arbitrary minimum row count. No GPU or LoRA update has started from the 600 data at this writing.

**Failure handling:** The finite teacher wave may contain no-code plans, WEBGL/brush setup errors and provider stream-duration errors. Keep these separate from aesthetic failures. The runner's narrow opt-in WEBGL canonicalizer records raw and rendered program hashes and only repairs an unambiguous setup error; all scene-level admission still requires a real canvas and visual review.
