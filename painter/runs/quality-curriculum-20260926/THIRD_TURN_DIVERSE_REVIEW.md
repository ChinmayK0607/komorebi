# Third-turn correction review on observed canvases

**Hypothesis.** A third full-program painting based on the exact second canvas can improve structure, material and beauty without inventing a new reference. The matched baseline is each subject's own second-turn canvas on the identical photo or text prompt. This is a nonblind teacher-data test, not a student-model gain. The [public source index](PUBLIC_SOURCE_INDEX.json) binds every source archive/revision; each collected run summary binds input, prior program/canvas, new program/canvas and pinned renderer `ad440b1aa8612e293b52fa5e68c2252926722852155eb8cd145d369a862a8a63` by SHA-256.

Four original third-turn programs were authored with Astra-high after direct inspection of the current canvas: soup, bears, potter and bird. On finite Codex Cloud Linux CPU, soup, potter and bird rendered valid; bears failed before a completed canvas because the pinned p5 runtime does not expose `quadraticVertex`. The original failure is retained. A separately packaged candidate replacing that short fur-curve call with supported vertices rendered valid. Static syntax and the previous contract had passed the original; the current contract now rejects `quadraticVertex` before packaging. The soup/bears subrun was 1/2 valid in 42 seconds wall time; potter 1/1 in 71 seconds; bird 1/1 in 14 seconds; bear runtime repair 1/1 in 32 seconds. All used a 600-second per-program limit and two worker slots. CPU busy fraction and billed cost were not instrumented; no GPU was rented. The source commits were `adfc18d4ff5d43ec28f84bdc442d97caab18c599` for the first three subruns and `d43e4926c62a4ad7ab634ee1b19efcf004badfef` for the repair.
