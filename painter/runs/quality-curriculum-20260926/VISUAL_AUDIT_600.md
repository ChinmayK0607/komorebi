# Teacher 600 render and visual triage, 2026-09-27

The hypothesis was that a large, mixed first-paint pool would yield directly useful teacher targets and correction states. The matched baseline for each output is its own prompt or exact photo reference. This is teacher-data screening, **not** a student-model improvement evaluation. Source Git revision before this audit was `5bd0fd5a30ef72cd433def2d423c8335f791e6f0`. The [render sweep record](RENDER_600.md) identifies immutable source bundles, CPU jobs and public receipts. The local audit manifest SHA-256 is `d12eff623986381b3d7560b8381dfccaa460c91b4410260f0ca915d0ef9858c2`.

The 600 distinct raw inputs consist of 290 text prompts and 310 photo references. The original programs rendered 578 valid canvases; 14 static runtime alternatives and three performance alternatives recover another 17 distinct inputs. **595/600 have a valid canvas.** Five photo tasks remain censored by the 600-second render deadline. These are valid-canvas counts, not visual-quality wins. Rendering used Codex Cloud CPU jobs, with no GPU. Worker concurrency and summed batch wall time are in `RENDER_600.md`; neither CPU busy fraction nor Cloud cost was instrumented, so no utilization or dollar claim follows.

The [combined 600-task gallery](../../collected/quality-curriculum-20260926/rendered-cloud/teacher600-gallery/index.html) preserves the original outcomes. The [595-canvas visual audit gallery](../../collected/quality-curriculum-20260926/rendered-cloud/teacher600-visual-audit-v1/index.html) shows the selected valid canvas beside its prompt or reference, including its repair route. The packet pins each canvas and input by SHA-256 and records the five censored input IDs.

Luna-low produced provisional labels on all 595: 10 A, 371 B and 214 C. **These counts are not accepted quality statistics.** The labels are strongly confounded with input mode: all 290 text cases are A/B, whereas 214 of 305 photo cases are C. Many explanations are template-like; a parent spot check found a photo waterfall rated B despite losing the waterfall's structure. This first pass is useful for browsing candidates, but not as a training filter or a calibrated judge. No pairwise comparison with a student baseline was run.

Parent visually inspected all ten Luna A nominations full-size and recorded canvas-hash-pinned decisions in [PARENT_A_REVIEW.json](PARENT_A_REVIEW.json) (SHA-256 `f69e96de8495aff7fde1e46b3089f4995acf08aab2c8384c3a608d54fb13519e`). **Zero of ten pass the direct high-quality SFT bar.** Seven are usable as correction seeds; roast vegetables, the noodle stall and the camel caravan are too sparse or structurally wrong for direct imitation. For example, the camel caravan reads as repeated stick figures rather than distinguishable camels and riders. The frog and lamp are pleasant simple illustrations but remain flat. This review covers the ten nominated A cases and selected other spot checks, not a parent full-size inspection of every canvas.

Decision: do not export the 595 valid canvases wholesale as SFT positives. Preserve the full gallery as candidate and failure evidence. The next data-generation wave should use exact prior canvases for turn-inspect-correct demonstrations, especially on recognizable B candidates, and compare corrected canvases with their own prior version and source reference. Future judging must be calibrated on parent-labeled cross-mode examples before it can gate training.
