# Repair plan for the 600 teacher tasks, 2026-09-27

The hypothesis is that a render-inspect-revise teacher loop can produce canvases that are visually better than the exact first paintings. Each task's first painting is its matched baseline. A renderer-valid program, syntactic p5.brush use, or a provisional uncalibrated quality grade is insufficient for SFT admission.

The [full local repair inventory](../../collected/quality-curriculum-20260926/teacher600-repair-inventory-v1/manifest.json) contains all 600 task identities and hash-pinned evidence paths; its SHA-256 and counts are frozen in [the tracked summary](REPAIR_INVENTORY_600_SUMMARY.json). There are 595 valid first paintings and five render-time censored photos. Of the valid canvases, 75 have no actual brush-paint call and 520 have at least one. Eight of the 75 were tested with deterministic native-to-brush translation. All 16 images rendered, but [parent visual review](SOL_BRUSH_PILOT_REVIEW.json) preferred the original in every pair, so that conversion is excluded. The remaining 67 native-only cases need a new teacher painting rather than blind API substitution. The 520 brush-using cases still need visual comparison; the presence of brush calls is no quality grade. None of these 600 are admitted by this inventory.

A separate [fixed-seed twelve-canvas cross-mode spot check](SPOT_CHECK_600.md) found recognizability in several first paints but weak opaque form, repetitive marks, transparent subjects and schematic people/machines. All twelve fall below the direct high-quality SFT bar. This is a small diagnostic sample, not an estimate of the full pool's acceptance rate; it supports correcting or redrawing selected cases rather than treating renderer validity as quality.

The first finite correction pilot compares MiMo Flash on a simple frog to MiMo Pro on a structurally harder container stacker, with at most four turns and the exact original canvas available from the first request. The subsequent rendered canvas is shown to the model each turn. The source program, source prompt, prior canvas, every response/program/canvas, render errors and token counts are preserved. Its Cloud run uses no GPU and publishes evidence to public Hugging Face only after SHA-256 verification. The exact stage script and run settings are in [stage_sol_redo_pilot.py](stage_sol_redo_pilot.py) and [run_sol_redo_pilot_cloud.sh](run_sol_redo_pilot_cloud.sh); source Git commit `9047488`.

After collection, choose the best *valid* turn for each scene by direct side-by-side inspection against the first paint and the source brief. Record remaining weaknesses even for a winner. Keep losing and invalid turns as correction states, not positive targets. If the pilot improves at least one scene, reuse its prompt/renderer loop in balanced text and photo waves; include easy shapes before complex people, animals and machinery. If it improves none, revise the prompting and program medium before spending on a broad wave. A short LoRA continuation follows only a materially larger, diverse set of accepted targets, and is compared on held-out text and photos against its exact initializer. This is a quality selection decision, not a training pause imposed by an arbitrary count.

The [next eight inspected correction states](NEXT_REPAIR_8.json) are prepared without paid calls: four text scenes and four photo scenes, ordered from a carved duck and avocados to a dog portrait and complex landscape. Each row pins source and first-paint hashes plus a parent-observed structural weakness. The teacher runner now supports a hash-checked source photograph and first-paint image in the same initial request, then the actual revision canvas on subsequent turns. This keeps photo-to-painting correction tied to the real reference rather than only to a flawed prior. Their rights-screened 1,458,410-byte [source bundle is public and anonymously hash-verified](NEXT_REPAIR_8_PUBLIC.json) at dataset revision `59e7f3aa31ca80a72f8d5a9849218bed3ac2afaf`, archive SHA-256 `0e1cfcd4b18e53c6851f41177a34c13f330aa38e35cefa675a7d37410f2af337`. It contains candidate inputs and priors only, no new teacher paintings or training admissions.

The [two-scene MiMo correction pilot](SOL_REDO_PILOT_REVIEW.json) finished four turns per scene and its complete public evidence was collected in a [matched visual review](../../collected/quality-curriculum-20260926/rendered-cloud/sol-redo-pilot-20260927/review.html). Flash produced three valid revisions of the frog; its best turn improves pose and toes, but mechanical eyes, rain and droplets leave beauty preference uncertain. Pro produced one valid port revision, which improves depth, lighting, people and port structure over the original but loses the reach stacker's large rubber tires. Neither is yet admitted as an SFT target. In both episodes, the first response hit the 16,384-token cap without a sketch; Pro then had two renderer errors in its brush pass. The Flash public result was recovered without rerunning paid calls by anonymously verifying its two uploaded parts, every exact source hash, and all three rendered program/canvas pairs. The [recovery script](recover_sol_redo_pilot.py) published a hash-verified receipt.

The next eight-scene mixed wave is staged with five Flash and three Pro tasks, including both text and photo references. The pilot changes are deliberate: a complete runnable sketch is required before prolonged planning, p5.brush accents are optional and isolated from the opaque base painting, explicit low reasoning is requested, and the per-response ceiling rises to 32,768 to avoid the prior first-turn truncation. The local dry-runs selected exactly eight scenes, 32 maximum provider calls, two generation and two render workers per tier, and made zero paid calls. The immutable source archive and exact photo rights metadata are pinned above; the runner stages its own Git source, reference, prompt and configuration hashes. The baseline for every repair remains its exact first paint. The next decision is visual pairwise selection, not syntactic validity.

The Pro tier of that wave has published and been hash-collected: three episodes, twelve response turns, eight valid canvases and four invalid turns, with 225,251 total tokens and incomplete monetary cost reporting. All three first turns produced visible code rather than exhausting the output limit, but two wrongly used a 2D `createCanvas(600, 600)` despite a WEBGL contract, causing brush-resolution errors; the dog also had a duplicate global identifier error. Subsequent turns repaired those faults. The three final canvases are visibly stronger than the first paints, while still missing specific requested features: dog head tilt, single rowboat figure, and rust beach. They remain relative-quality candidates rather than direct SFT targets; Flash and the final eight-case selection are pending. For **future** runs, the benchmark now has an opt-in narrow WEBGL setup canonicalizer that records raw and rendered code hashes and only acts on an unambiguous 600×600 2D setup followed by the required WEBGL coordinate translation. It is not retroactively applied to this live wave.

Measured cost and utilization: the matched translation render took 612.351 wall seconds on Codex Cloud CPU with two render workers; CPU busy fraction and dollar charge were not instrumented. The MiMo pilot used 146,129 total Gateway tokens over eight response turns, but Gateway returned no complete monetary charge. It used no GPU. An instantaneous GPU reading is therefore not applicable, and Cloud CPU saturation was not measured. No watcher or scheduled task was created.
